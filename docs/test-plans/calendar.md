# Тест-план: страница Календаря (`/calendar/`)

Каталог тест-планов: `docs/test-plans/` (см. также `login.md`).
Обозначения: ✅ — покрыто тестом · ⚠️ — пробел (кандидат) · ⚠️* — частично.

## Данные и предусловия (единые для всех тестов)

- **Роли**: `student` / `moderator` / `admin` (поле `User.role`; `IS_STAFF` = admin|moderator).
- **Тестовый студент**: `+73333333333` / `stud123`, `allowed_tariffs=[3]`, баланс 5500 (read-only s5; мутирующие тесты — свежий `registerNewUser()`).
- **Мутирующие тесты**: `registerNewUser` + `setBalance` + `setAllowedTariffs`, в конце `deleteTestUser`; баланс/тарифы s5 возвращаются.
- **Календарные события**: всегда на чистой будущей дате `CLEAN_EVENT_DATE` (+1 год, динамически) с `cleanupEventsOnDate()` перед созданием; даты не пересекаются с `SHOP_EVENT_DATE` (2030-08-22) и `futureDay(364)` у профиля (параллельный прогон). **✅ Сделано (рефакторинг дат + отказ от refetch)**: хелпер унифицирован в `futureDate(daysFromNow, opts)` (от today). Дата изоляции восстановлена: `CLEAN_EVENT_DAY=365`, `CAL_DAY_OFFSET=CLEAN_EVENT_DAY+2=367` (админ-тесты создания событий). `navigateToDate` — чистый `gotoDate` + `waitForEvents` (без `refetchEvents()`-дёрга). Это убрало 6 регрессов «событие не подгрузилось» (раньше цель была внутри уже загруженного месяца и `gotoDate` не вызывал refetch — приходилось костыльно дёргать `refetchEvents()`; сейчас изоляция на далёкой дате +1 год гарантирует фактический запрос событий).
- **Тарифы**: через `getResolvedTestTariffs(page)` (резолв по семантике), НЕ литеральные id: `group` (экс-«Йога», 700 ₽/абонемент 4500/8), `forbidden` (без абонемента), `lite`/`pro` (по имени), `split` (по типу; канонический id 3).
- **Часовое ограничение**: запись/отмена заблокированы при старте занятия ≤4 часа от сейчас; для обхода — `moveSessionToPast`.
- **Поля формы события**: класс-тайп `event-class-type`, час/мин `event-start-hour/minute`, длительность `event-duration` (min 15, step 15), зал `event-hall`, тариф `event-tariff`, вместимость `event-max-participants` (кнопки `capacity-btn` 2–10), повтор `event-recurring` + `event-recurring-count` (2–12, дефолт 4). Обязательные: тип, зал, тариф, время. **👉 Кейс-фича**: сделать кнопки вместимости **1–10** (есть индивидуальные занятия на одного студента) — нужно менять шаблон `calendar.html:88-96` + тест 1482.
- **Модалки (все `.modal-overlay`, скрыты по умолчанию)**:
  - `#eventModal` (`event-modal`) — создание/редактирование/запись; вкладки `tab-class` «Занятие» / `tab-attendance` «Запись»; закрытие `event-modal-close`; кнопки `event-cancel-btn` / `event-delete-btn` (скрыт при создании) / `event-save-btn`.
  - `#deleteConfirmModal` (`delete-confirm-modal`) — удаление серии: radio `delete-single` / `delete-series`, инфо-строка `deleteSeriesBookingInfo` (число записей), `cancel-delete-btn` / `confirm-delete-btn`.
  - `#confirmModal` (`confirm-modal`) — подтверждение действия: `confirmMessage`, `confirm-cancel-btn` «Нет» / `confirm-ok-btn` «Да».
  - уведомления (`notification-modal` / `notification-message` / `notification-ok-btn`) — центрированы, текст + isError. **👉 Уточнение**: все модалки `.modal-overlay` — `flex centered` (гарантируется CSS), поэтому положением покрыты; центрирование уведомления уже тестируется (480). Если какая-то конкретная модалка визуально не по центру — указать, разберу отдельно.
- **Виджеты FullCalendar**: переключение вида `fc-view-month/week/day`; «Сегодня» `fc-today-button`; `fc-next-button`/`fc-prev-button`; легенда залов `.hall-legend`; нижняя панель «Главная/Магазин/Профиль/Расписание-активна».
- **API календаря**: `GET /api/calendar/events/?start&end`; `GET /api/calendar/events/<id>/attendance/`; `POST .../attendance/add|remove|update/`; `GET .../recap/` (recap для модалки удаления); `POST /api/calendar/events/` (create/update/delete).
