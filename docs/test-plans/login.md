# Тест-план: страница Входа (`/login/`)

Кастомная страница входа для учеников (Django view `login_view` + `LoginForm` + `PhoneAuthBackend`).
Обозначения: ✅ — покрыто тестом · ⚠️ — пробел (кандидат) · ⚠️* — частично.
Тесты Playwright — в `tests/auth/login.spec.ts` (26 тестов, прошли все на :8003).

## Данные и предусловия (единые для всех тестов)

- **Роли**: `student` / `moderator` / `admin` (поле `User.role`; `IS_STAFF` = admin|moderator).
- **Канонический тестовый студент (s5)**: `+73333333333` / `stud123`, баланс 5500, `allowed_tariffs=[3]` (гарантируется `runserver_test.py._ensure_test_users()`, read-only).
- **Мутирующие тесты** (создание пользователей для проверки «правильный пароль» и т.п.): `registerNewUser(uniquePhone())` + в конце `deleteTestUser`; либо `test_user_info`/`test_authenticate` для API-проверок.
- **Админ**: `admin` / `admin123` (вход через стандартный Django `/admin/login/`). **Модератор**: `moderator` / `admin123` (или `mod123`) — `loginAsModerator` перебирает пароли.
- **Поля формы входа** (`core/forms.py` `LoginForm`):
  - `data-test-id="login-username"` (`id_username`, autocomplete `tel`) — номер телефона.
  - `data-test-id="login-password"` (`id_password`, autocomplete `current-password`).
  - `data-test-id="login-submit"` — кнопка «Войти».
- **Общая ошибка формы** (`non_field_errors` → `.alert.alert-error`, текст «Неправильное имя пользователя или пароль…»); **ошибки поля** — `.error` под полем.
- **Ссылки на странице**: «Зарегистрироваться» → `/register/`; «Вход для администратора» → `/admin/`.
- **VK-блок**: `#vk-login-container` (рендер виджета в `vk-auth.js`, SDK вендоренный `vkid-sdk`); при возврате с `?code=` на `<html>` ставится класс `vk-return` (форма скрыта, показывается спиннер), при сбое — `vkAuthFlowFailed` снимает класс и возвращает форму.
- **Модалка уведомлений** (`notification-modal` / `notification-message` / `notification-ok-btn`) — из `auth_base.html`, скрыта по умолчанию.

### Маршруты (`yoga_crm/urls.py`)
- `GET/POST /login/` → `login_view`; `GET /register/`; `POST /logout/`.
- `GET /api/auth/vk/` (редирект из VK, `?code=` → на `/login/?code=...`); `POST /api/auth/vk/` (обмен code/token).
- DEBUG-эндпоинты: `POST /api/auth/test/authenticate/` (логин по username), `POST /api/auth/test/user-info/`, `POST /api/auth/test/delete-user/`.

### Логика входа (для тестов)
- `login_view` (views.py:1045): если уже авторизован → `redirect('home')` (`/dashboard/`). POST → `LoginForm` (валидация/нормализация телефона) → `authenticate(username=cleaned_phone, password)` → `login()` → редирект на `request.GET.get('next', 'home')`.
- `LoginForm.clean_username` (forms.py:144): убирает нецифровые символы (кроме `+`), `8XXXXXXXXXX` → `+7`, валидирует `^\+7\d{10}$`, иначе «Неверный формат телефона. Используйте формат +7XXXXXXXXXX».
- `PhoneAuthBackend` (auth_backend.py): **если во вводе есть цифры** — «телефон-путь» (перебор всех пользователей, сравнение `normalize_phone(phone/username)` с вводом); **если цифр нет** — точное совпадение `username` (например `admin`). Неверный пароль/неактивный пользователь → `None`.
- `logout_view`: `logout()` → `redirect('login')`.

> **Phone-mask caveat**: маска на поле телефона ломает `fill()`. Использовать хелпер `fillPhoneField()` (`tests/fixtures/helpers.ts`).

## 2. Валидация и нормализация телефона

| Кейс | Ожидание | Покрытие |
|---|---|---|
| Пустое поле телефона, пароль задан | `.error` под полем «Номер телефона обязателен» (красным, `#e74c3c`; required-сообщение задано на поле `error_messages`), не `alert-error`, без редиректа | ✅ «пустой телефон — ошибка "Номер телефона обязателен" красным под полем, без редиректа» |
| Пустой пароль | `.error` под полем пароля «Пароль обязателен» (красным, `#e74c3c`; не `alert-error` — required на поле, а не `non_field_errors`), без редиректа | ✅ «пустой пароль — ошибка "Пароль обязателен" красным под полем, без редиректа» |
| Маска телефона | при загрузке поле = `+7 (` и placeholder `+7 (___) ___-__-__`; ввод цифр форматируется в `+7 (XXX) XXX-XX-XX`; при потере фокуса неполный номер очищается | ✅ «Телефон-маска» (3 теста: инициализация, ввод, blur-очистка) |
| Ввод с пробелами/скобками/дефисами («+7 (900) 123-45-67») | формат принят (нормализуется), без ошибки поля телефона | ✅ «нормализация: ввод с пробелами/скобками/дефисами» |
| Ввод от «восьмёрки»: `8XXXXXXXXXX` (11 цифр) | конвертируется в `+79...`, вход успешен для нужного аккаунта | ✅ «нормализация "восьмёрки"» |
| Неверный формат (короткий номер, без `7`) | `.error` «Неверный формат телефона…» | ✅ «некорректный формат телефона — ошибка поля» |
| Логин по username без цифр (`admin`) | точное совпадение `username`, вход возможен | ✅ «admin логинится по username через backend» (`test_authenticate`) |
