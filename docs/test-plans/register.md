# Тест-план: страница Регистрации (`/register/`)

Кастомная страница регистрации для учеников (Django view `register_view` + `RegistrationForm( UserCreationForm)`).
Обозначения: ✅ — покрыто тестом · ⚠️ — пробел (кандидат) · ⚠️* — частично.
Тесты Playwright — в `tests/auth/register.spec.ts` (26 тестов, прошли все на :8003).

## Данные и предусловия (единые для всех тестов)

- **Свежий пользователь регистрируется**: `registerNewUser(uniquePhone())` (всегда чистит куки, после успеха ждёт `**/dashboard/`); в конце — `deleteTestUser`.
- **Дефолты нового пользователя** (`UserDefaultSettings.get_defaults()`, dev_db pk=1): `role='student'`, `balance=0.00`, **без** `allowed_tariffs` и групп. `username` = очищенный телефон (`+7XXXXXXXXXX`).
- **Хелпер заполнения** `fillRegisterForm` (tests/fixtures/helpers.ts): по умолчанию имя «Тест», фамилия «Тестов», `phone='+79001234567'`, `password1=password2='Test1234!'`. Пароль теста-юзеров `stud123` проходит валидаторы (6 симв., буквы есть, не распространённый).
- **Канонический s5** (`+73333333333` / `stud123`) используется ТОЛЬКО для кейса «дубликат телефона» (read-only, не удалять).
- **Поля формы** (`core/forms.py` `RegistrationForm`):
  - `data-test-id="register-first-name"` — «Имя» · `register-last-name` — «Фамилия» (оба required → «Обязательное поле.»).
  - `data-test-id="register-phone"` (`id_phone`, autocomplete `tel`, help-text «Введите номер телефона в формате +7XXXXXXXXXX`, маска) — required → **«Номер телефона обязателен»** (`error_messages` на поле).
  - `data-test-id="register-password1"` / `register-password2` (тип `password`) — required → «Обязательное поле.».
  - `data-test-id="register-submit"` — кнопка «Зарегистрироваться».
- **Ссылка на странице**: «Уже есть аккаунт? Войти» → `/login/` (relative href).
- **`novalidate`** на `<form>` — HTML5-валидация отключена, работают только серверные сообщения (`.error` под полем).
- **Модалка уведомлений** (`notification-modal`/`notification-message`/`notification-ok-btn`) из `auth_base.html` — скрыта по умолчанию.

### Логика регистрации (для тестов)
- `register_view` (views.py:1006): **если уже авторизован → `redirect('home')`** (`/dashboard/`). POST → `RegistrationForm.is_valid()` → `form.save(commit=False)` → `username = cleaned phone` → `role/balance` из `UserDefaultSettings` → `allowed_tariffs`/группы (если заданы) → `login(request, user)` → `redirect('home')`.
- `clean_phone` (forms.py:95): убирает нецифровые символы (кроме `+`), `8XXXXXXXXXX` → `+7`, валидирует `^\+7\d{10}$` («Неверный формат телефона…»), **уникальность** «Пользователь с таким номером телефона уже зарегистрирован».
- **Валидаторы пароля** (settings.py `AUTH_PASSWORD_VALIDATORS`): `UserAttributeSimilarity` + `YogaPasswordValidator` (**мин 6 симв., хотя бы одна буква** — «Пароль должен содержать минимум 6 символов.» / «…хотя бы одну букву.») + `CommonPasswordValidator` («Введённый пароль слишком широко распространён.») + `NumericPasswordValidator` («Введённый пароль состоит только из цифр.»).
- Несовпадение `password1`/`password2` → «Введенные пароли не совпадают.»
- ⚠️ **UX-пробел**: на странице НЕ выводится help-text требований к паролю (`password1.help_text` в Django 6 пуст, шаблон рендерит `if`). Зафиксирован тестом «help-text отображается только у телефона…».

### 🔧 Баг, найденный тестами (исправлен)
`phone-mask.js` инициализировал `id_phone` **дважды** (label-цикл + `specificIds`): второй вызов переформатировал префикс `'+7 ('` в `'+7'`. На `/login/` не проявлялся (у `LoginForm` пустой label → label-проверка не срабатывала). Исправлено guard-флагом `dataset.phoneMaskInit` в `initPhoneMask` (core/static/core/js/phone-mask.js). Обе страницы теперь стартуют с `+7 (`.

> **Phone-mask caveat**: маска на `id_phone` ломает `fill()`. Использовать `fillPhoneField()`. Маска идентична логин-полю (init `+7 (`, ввод форматирует, blur с неполным номером очищает поле).
